### 2.2 第一研究点：具体做什么

研究目标暂定为“面向水下实例分割的特征/掩码与边界适配”，题目随证据调整。候选来自 WaterMask 的 DSGAT、MFRM、BLL；三个名称不是三个已经成立的创新点，也不是承诺必须全部保留。

实施前逐个填写适配说明：原模块解决什么问题、在 WaterMask 哪里使用、迁移到 Mask2Former 的哪个位置、输入输出是什么、哪些部分不能直接照搬、自己的适配修改是什么、如何验证。**具体插入位置和实施顺序目前未定，不能把之前讨论的猜测写成已实现结构。**

原则是从与 P2 问题最相关、改动最小且能单独验证的一项开始；第一项不理想时，先检查正确性和假设，不立即堆叠另外两项。

### 2.3 第二研究点：候选保留，但不假装已经确定

保留此前讨论的 DINOv2 / DiveSeg 方向，重点候选是“预训练特征的水下适配”，与第一点的掩码/边界适配形成区别。DINOv2、DiveSeg 是研究参考，不代表本项目已采用其某个确定实现。

P6 必须先阅读并核对原论文/源码，再在以下范围选择一个具体方案：冻结特征与轻量适配、或针对水下特征的一个小改进。不能简单把骨干换成 DINOv2 就当成新的研究贡献。若涉及额外预训练数据、不同模型规模或特征结构，需增加合适对照并披露差异。

TIDE 优先作为 P2/P5 的误差分析候选工具；它本身不作为默认第二创新点。采用前核对实现支持的任务与错误定义；未适配时不能把检测框诊断结论直接写成掩码边界结论。

第二点至少需要明确：基础方法、独立问题、自己的改动、相同条件下的对照、消融以及与第一点的关系。先做最小可行验证，再决定正式长训练。若该线成本明显过高或没有独立问题，记录原因并与用户确定替代方案，不擅自切换到生成数据或同时新开多条线。

### 2.4 评价与已有方法比较

- E0 32.6 是原版基线成绩；改进贡献通过相同协议下的增量证明，不用超过 WaterMask 26.4 代替自身消融。
- WaterMask 官方值可以作为带来源标记的参考；若自行复现，使用相同 UIIS 数据规则及评价流程，记录预训练/训练策略差异。是否额外完整训练 WaterMask，取决于论文证据需求，尚未执行。
- 不通过测试 AP 自动挑 checkpoint，继续使用预先固定最后轮次。测试集已被评估和查看，后续根据它选设计会有测试集反馈影响，论文如实说明；不擅自更改用户已确认的原始划分。
- 正式实验前登记配置与选模规则，避免大量试参后只挑最好分数。需要新的验证设计或额外数据集时，先明确协议再实施。
- 不预先承诺提升几个点。结果不涨先排查实现、加载、梯度、训练稳定性及指标一致性；仍无增益就保留负结果并回到假设，不为了凑论文强行宣称有效。

## 7. 术语与论文比较规则

**COCO** 有两个用途：模型先在 COCO 上学习通用分割；本次 UIIS 测试使用 COCO 评分规则。`coco/segm_mAP` 指评价器，不表示用普通场景替代水下图片考试。

- **IoU**：预测区域与人工区域的交集面积 / 并集面积。
- **AP50 / AP75**：用 IoU >= 0.50 / 0.75 匹配类别正确的实例，再综合预测排序、误报和漏检计算精度。
- **主 AP**：在 0.50、0.55……0.95 十个阈值及类别上平均，不是像素正确率或单张图的重合率。
- JSON 的 0.326 写成 32.6 AP；差值 6.2 是 AP 点数，不是相对提升 6.2%。
- 图上置信度阈值 0.5 与 AP50 的 IoU 0.5 不同；AP75 更严格，但不等于边界专用指标。

定义来源：[COCO 评估实现](https://github.com/cocodataset/cocoapi/blob/master/PythonAPI/pycocotools/cocoeval.py)。
