# 同格冲突分配：现有密集样本可用单槽位分开

2026-11-01。复用已通过身份同步验收的固定6图、12次增强记录。纯本地GT几何计算，无服务器、模型、推理或训练。没有扩样、调阈值、改输入尺度或最终100输出数。

## 结论

之前“每个实例只取最靠近质心的一个前景点”产生22处同格冲突。本次允许每个实例从自身前景实际占据的stride8格子中选择一个，再做一对一分配，1076条保留的小目标记录全部可分到不同格子。共25条记录改变原先选格，22处冲突全部消除。

因此当前样本不支持立即增加每格多槽位、改高分辨率骨干或扩大query总数来解决这批位置冲突。该结论仅限这批GT辅助分配，不保证其他图片/增强，也不证明学习后的query召回。

## 明确的监督分配规则

1. 使用annotation_id和original_area确定原图小目标，随后只检查当前增强后实际保留的mask；不把大目标裁小混作原小目标。
2. 对每个目标列出其前景像素实际占据的所有stride8格子。纯背景格不可作为该目标的位置标签；不把“占据格”改成整格前景mask监督，避免重走旧BLL的目标外扩问题。
3. 在目标与候选格之间求最大数量的一对一分配：一目标一格，一格一目标。搜索优先靠近原代表格，其次前景覆盖数及行列顺序；原始ID排序确保结果可复现。算法保证当前候选集合内的最大匹配数，不声称全局最小移动距离或最优AP。
4. 在分配格内再取真实前景像素记录坐标，保留GT ID对应关系。格内坐标可用于核验；若未来网络需要预测亚像素位置，必须明确新增预测和监督，不能推理时直接使用GT坐标。
5. 若未来出现无法分配的目标，显式记录未分配ID及容量不足的候选集合；不能静默覆盖同格标签。本批无此情况。

这是训练标签构造候选。推理时没有GT，仍需目标性/位置预测产生候选；不能把本脚本的GT分配结果塞给验证集推理。

最大单次增强158个原小GT。仅按全部小GT计算，固定K20在这些增强记录中会有876条超出容量；这不是原版残余漏检数，不能据此选择K158，也不能说实际补漏必然缺876个位置。位置监督可以覆盖所有小GT，最终实例分支的固定query预算仍须按已冻结任务定义与残余目标统计单独决定。

本次不施加局部极值抑制或固定距离排斥。唯一格不代表格子之间隔得远；推理时相邻峰值仍可能竞争。不得把“GT格子能分开”扩大为“FastInst式局部峰值一定能留下所有实例”。也没有证明所选格的特征中心已准确表达目标，格内一小部分前景不等于该特征可分辨。

检查包括：每个分配位属于该实例前景占据格、分配格互不重复、格内坐标确实为前景、原输入顺序反转仍得到相同结果。三个小构造覆盖需重新分配才能匹配、单槽位容量不足、双槽位恢复；无法完全匹配时用交替可达集合核验容量缺口，当前真实样本没有缺口。源码及记录均保留，不使用模型或额外训练拟合。
