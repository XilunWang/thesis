# BLL受控短试跑协议（拟执行，尚未启动）

2026-10-21。目的仅为检查连续更新、真实增强、保存恢复与资源稳定性，不评估AP收益，不是E1正式实验，也不重训E0。

## 两组固定设置

| 项目 | 预定规则 |
| --- | --- |
| 对照 | A：原版Mask2Former；B：独立BLL候选head，loss_weight=1、width=3（仅探针） |
| 起点 | 两组均严格加载同一E0 epoch_36模型参数，优化器重新初始化；不继承E0的36轮优化器/调度进度 |
| 作用边界 | 这是已训练E0上的技术短试跑，不等于正式E1从COCO预训练起跑；不能拿短试跑与32.6直接比较收益 |
| 数据 | 官方train.json按img_id排序前16个ID，运行前保存ID/文件名/图片与标注哈希；不按损失或目标大小换图，未通过的数据样本如实报错 |
| 顺序 | batch=2，顺序循环16图；两组每步拿同一对图片，总计每组20步，共40步 |
| 增强 | 原E0训练pipeline：随机翻转、LSJ、裁剪、过滤、1024补齐；不使用诊断专用固定比例0.503 |
| 随机性 | 每个图像出现次数固定种子20262000+2×step+slot（step=0..19、slot=0/1）；前向/损失采样种子20263000+step；保存种子协议，不以GPU逐位轨迹等价为前提 |
| 优化器 | 原E0 AdamW配置和参数分组、梯度裁剪；基础lr=1e-4，backbone乘0.1，原weight_decay等完整配置需写入manifest |
| 学习率 | 20步内保持各组初始lr，不把20步伪装成20轮或触发E0第27/33轮衰减；调度状态仍记录 |
| 精度/硬件 | 现有V100，单进程FP32、无AMP/梯度累积；两组相同cuDNN设置，依次执行 |
| 检查点 | 每组第10步保存并退出进程，新进程严格恢复从第11步继续；第20步保存最终检查点并结束 |
| 时间预算 | 整个两组短试跑最多10分钟；超时保存诊断并停止，不自动延长或调整batch |

保存项必须包含模型参数/缓冲区、优化器动量/步数/参数组、调度器、wrapper计数、已完成步数、下一数据游标、Python/NumPy/torch/CUDA随机状态、完整配置/协议哈希。恢复时校验配置、数据规则和步数，拒绝不匹配或覆盖旧运行。使用独立work_dirs/bll_short_pilot下A/B目录，检查点不写入E0目录。

## 必须记录及停止条件

每步记录原损失分量及loss_bll、裁剪前梯度范数、学习率、真实实例数/匹配数、BLL选区像素数、GT缩小消失数、显存及耗时。原版与候选损失变化只作运行诊断；不同轨迹下的损失值不能当精度收益。

出现异常、OOM、任一非有限loss/梯度/参数、恢复状态不一致、数据游标错位、读取到测试集或预算耗尽时立即停止该次试跑，保留失败日志，不自动重启/续到满预算。BLL连续3个有非空GT的步骤无任何选区，或任一非空GT在BLL网格完全消失时，暂停并检查样本，不能静默忽略。原pipeline合法裁空样本记录为负样本，不据此换图。

成功仅表示两组均完成20步、状态恢复一致、记录完整且无上述异常。没有“损失必须下降”或“AP必须提高”的通过条件；不评估691张测试集、不挑最好checkpoint、不改学习率/带宽/权重再试。正式E1需另立协议、明确假设和初始化，不能自动从本次续成长训练。
