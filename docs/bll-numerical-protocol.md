# GPU完整模型数值验收协议

2026-10-21，运行校准前固定如下规则，不根据候选验证结果调整。

范围仍为原有4张训练图/6视图/3批、E0权重、单进程FP32、相同种子，开启cuDNN确定性、关闭benchmark。校准与验证是不同进程的新运行，但使用同一固定输入；不是未见图像上的泛化验收，也不是统计置信区间。

原输入、预处理、最终输出、原损失及torch CPU/CUDA RNG仍要求精确相等。只重新定义梯度比较，原逐元素atol=1e-6/rtol=1e-5检查仍保存为legacy_elementwise_check，不删除旧失败。

对每个参数张量分别记录两个无量纲指标：max(abs(g-g_ref))/max(max(abs(g_ref)),1e-12)及norm(g-g_ref)/max(norm(g_ref),1e-12)。前者防止整体范数掩盖局部错误，后者控制整体偏差。梯度必须有限、参数名集合必须相同。

每批原模型运行5次，第一次数值为参考，后4次产生误差。对每参数每指标分别冻结阈值max(观测最大误差×5,32×FP32 epsilon)，并要求阈值不超过1e-4，否则校准失败。倍数5是预先选择的工程余量，不是显著性或置信保证；32 epsilon约3.8147e-6提供有限舍入余量；1e-4硬上限防止校准将大错误常态化。

校准只看原模型，冻结JSON后记录SHA256。验证另起进程，重新加载同权重：每批新原版参考、2次额外原版重复、2次关闭BLL对照、1次开启BLL功能检查。验证不能更改冻结阈值。原版重复和关闭BLL都须满足两项指标；开启BLL必须保留原输出/原损失/RNG、有限反传、参数未更新等既有检查。

负对照在每个非零参数梯度上分别注入1%的整体缩放错误、单个峰值位置0.1%峰值幅度的加性错误；保持损失/输出不变以单独考验梯度指标，要求全部检出。这只能说明对这两类指定扰动有检出能力，不能证明所有错误都可检测。

所有输入/种子、阈值、指标和负对照记录在reports/bll-numerical-protocol。任一门槛失败则报告失败，不自动调参重试。无优化器、训练或新AP评估，未改变正式训练配置。

复现分两次独立进程执行，先完成校准、保存冻结文件，再执行验证：

```bash
.venv/bin/python -B scripts/verify-bll-real-images.py --deterministic-cudnn --numerical-stage calibrate --output reports/bll-numerical-protocol/calibration.json
.venv/bin/python -B scripts/verify-bll-real-images.py --deterministic-cudnn --numerical-stage validate --output reports/bll-numerical-protocol/validation.json
```

冻结文件默认reports/bll-numerical-protocol/frozen.json；脚本拒绝覆盖既有报告和校准协议。校准完成后阈值不可由验证过程修改。

## 本轮实际结果

校准15次完整前后向（每批5次原版）、另起进程验证18次完整前后向（每批6次），两阶段均退出码0，报告passed=true。每批345个参数张量；三个批次的最大冻结阈值分别3.49985976e-5、2.90930098e-5、2.19244317e-5，最小阈值均3.81469727e-6，均低于预设1e-4硬上限。

三批独立验证中的原版重复、关闭BLL对照各2次全部通过；开启BLL维持原损失、输入、最终输出及RNG一致，新增项有限正值，参数没有更新。每批345个非零参数张量的缩放/单点扰动均被检出，合计345×2×3=2070项指定负对照通过。首轮逐元素超差仍保留在旧报告与本次legacy_elementwise_check中，不重新解释成逐位一致。
