# UIIS公开强方法与比较条件审查

日期：2026-11-01。仅阅读公开论文、作者仓库和本地既有审计；没有连接服务器、下载模型、修改模型或训练。不是完整文献综述，也不是统一复测排行榜。

## 结论与决策

暂停单格邻居干扰候选的决定不变。优先把DiveSeg作为“已有强方法参照”核查，不直接迁移模块、不立项重训、不替换E0。它的分割头采用Mask2Former，说明“Transformer不能从水下适配受益”这一笼统判断不成立；但不能证明其方法迁移到本项目R50必然有效。

## 为什么不能直接比高低

两篇论文均报告UIIS3937/691、7类及mask AP，任务名称和数量可对齐；标注哈希、重复图处理、测试尺度、maxDets及实际预测尚未核验。USIS10K另一个数据集的显著实例结果不混入本表。

E0使用完整COCO实例分割预训练，36轮；DiveSeg采用DINOv2-L、Mask2Former头，论文预算batch8×30000步，区别远不止一个模块。不能声称35.6−32.6222就是模块收益，也不能把32.6222高于部分文献数字写成公平超越。既有ImageNet-only方案保持暂停，不为对齐论文补跑基线。

DiveSeg表3报告基础DINOv2+Mask2Former为30.9、完整模型35.6。但表3与正文对两个单模块增量的归属有不一致，进一步引用单模块收益必须查代码与配置，不能照抄文字结论。该论文未在主表给出小目标AP，尚不能断言它解决了本项目的小珊瑚漏检。

## 代码和权重入口

[作者仓库](https://github.com/ettof/Diveseg) README提供UIIS训练后权重链接；仅确认链接存在，尚未下载、验证内容或可访问性。它使用Detectron2，与本地MMDetection环境不同。

[eval.sh](https://github.com/ettof/Diveseg/blob/master/eval.sh)指向UIIS配置并使用eval-only；[train.sh](https://github.com/ettof/Diveseg/blob/master/train.sh)当前默认USIS10K、双GPU和resume，不能直接运行来复现UIIS。当前查看的是可变master，不是已冻结的复现实验版本。

## 下一项：一次有边界的复测可行性审查

1. 固定作者代码提交，检查UIIS配置继承、类别注册、测试变换、评价maxDets和权重身份；只读源文件，先不安装环境。
2. 核实发布权重获取条件、大小及推理显存要求，判断现有V100能否仅推理。不能因A100训练描述断言V100一定可行。
3. 条件满足再制定同691图只推理协议，保留作者原协议结果和本项目统一计分结果，不能混写。如果权重不可用或成本过高，则如实结束该参照复测，不自动转训练复现。
4. 有真实预测后再查小目标是否恢复、大目标是否保住，以及改善来自何种表征。仅凭论文还不足以选择新的自研模块。

没有新AP结果，没有AP提升保证。BLL、有效区域采样和邻居候选的负结果保留；官方划分及重复图不变。
