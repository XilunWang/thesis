# 位置提示如何参与 query：四例机制审查（2026-11-01）

本轮完成源码与接入方案审查；未修改模型、未执行服务器前向、未训练。下一项是一次有停止条件的冻结模型诊断，不批准新模块或训练。

## 1. 已有证据支持到哪里

## 2. 原版流程与明确的接入位置

依据保存的原版`reports/baseline-decoder-audit-20261031/head-source.txt`，不是依据PPT：

图像 → R50 → 像素解码器 → 三尺度memory与mask特征；100个学习query依次读取stride32、16、8的memory，循环三次，共9层。每层更新query再输出分类与mask，mask又决定下一层允许读取的区域。

当前位置头读取冻结R50特征，输出stride4位置分数。其分数与候选位置尚未进入上述query更新或最终分割。因此，位置覆盖增加不会自动变成Mask AP增加。

建议只检验一个假设：**已有query若在一次高分辨率读取中集中观察候选附近，能否形成原来没有的独立小目标掩码？**

精确插入点为第三个decoder层（循环索引i=2，首次读取stride8 memory），`layer(... cross_attn_mask=attn_mask)`之前。诊断副本仅在这一层用候选附近窗口替换原cross-attention允许区域，随后恢复原有mask引导与全部后续层。原query内容、query位置嵌入、特征、分类头、mask头及权重均不变。更新的是分类与mask共同使用的query，不是在最后输出上补边界损失。

stride8是现有decoder直接读取的最细尺度，不需要新投影层；不声称它已经足够分离这些小鱼，也不声称更粗尺度不能工作。stride4位置只是转成stride8读取窗口，并非直接接入新的stride4 memory。

## 3. 最小无训练诊断协议

仅用上表3张图、原固定增强与E0权重；输入/GT哈希必须与前次缓存一致。所有参数冻结、eval模式、无优化器、无反传。

- 原版路径照常运行100个query，输出必须复现已有缓存。诊断使用独立副本，不能把额外query拼进原版自注意力或合并预测后声称原输出保持。
- 对每个已选候选格，用格中心`x=4*(id%256)+2, y=4*(id//256)+2`，映射到实际stride8 memory；不吸附到GT内部。检查有效区，越界明确失败，不静默换点。
- 固定允许中心周围3×3个stride8格（约24×24增强像素），与有效区相交。一次副本中的全部100个原query均使用该窗口，其余层保持原实现。使用全部query避免事后选“最好query”作为输入；但它是高预算机制探针，不是部署方案。
- 每个点另做四个固定偏移对照：增强坐标左、右、上、下各32像素，窗口尺寸相同。只依据有效区裁剪中心；记录实际中心及重复位置，不依据GT或输出挑方向。若与原窗口相同，该对照标记无效，不补搜位置。
- 原版3条完整路径，加4点×5条诊断路径，最多23条decoder路径；可复用冻结图像特征。预算到此为止，不增加尺度、窗口或训练步数搜索。
- 对照比较同一个GT在各路径最终100个query中的最佳IoU；同时按既有原后处理、score≥0.5、同类IoU≥0.5、全尺寸GT一对一规则报告实际检出。最佳IoU只作几何诊断，不能混称检出。记录每条路径所有GT的得失、额外误报及耗时/显存。
- 保留四例全部结果及失败；即使只一例成功，也不得只展示成功图。副本输出不与E0合并，不报告该诊断的正式Mask AP。

本次探索的保守继续条件：至少2/4目标形成IoU≥0.5的最终掩码，至少1/4成为同类、分数合格的一对一检出；对应GT必须在所有有效偏移对照中均未达到相同的检出条件，才有位置针对性的证据。有效偏移不足则该例不能算通过。此为预算决策门槛，不是统计显著性标准。

不满足时停止这一“单次局部注意力窗口”探针，不在本批案例继续调窗口找成功。失败不能证明所有可学习位置query方法无效，但现有证据不足以支持开训。

## 4. 为什么这还不是正式改进方案

四个点是通过GT关联挑出来的，实际推理不知道哪个点对应漏检，也不知道哪个query应该负责它。即使探针通过，仍需另行解决：不看GT的候选预算/分配、相邻实例竞争、背景候选过滤、额外预测排序，以及全样本收益与成本。不能直接把四例成功写成可部署的方法。

独立诊断副本只能保证原路径不受干扰；把副本结果融合进正式预测后，重复预测、误报及top100竞争仍可能降低AP。不能承诺“只改善小目标、不影响原结果”。

本轮结论：源码允许执行该有限诊断，值得先验证位置能否影响独立掩码形成；尚不值得继续位置头调参或全量训练。没有已验证的AP收益，也未作创新性认定。
