# 真实训练图上的BLL监督与梯度检查

2026-10-30。4张UIIS训练图、8个增强后匹配实例，加载E1 epoch36，在实际训练pipeline和模型train模式下前向/计算梯度；没有优化器、optimizer.step或训练更新。所有模型状态张量逐项与加载值相同，权重文件SHA256不变。

## 结论

**确认真实模型存在局部监督冲突，不再只是合成例子的推测。** 在被BLL选中、完整4×4格内前景占比大于0但不足50%的1577个格子中，982个（62.27%）出现原最终层mask BCE+Dice要求降低前景logit、BLL要求提高的相反方向。4张图均出现，不是只挑一个退化案例。

这支持优先修查“占有目标把部分背景格当完整前景”的机制。并非BLL整体处处抵消原损失，也不能证明此机制解释全部边界/AP下降，不能据此直接开新训练。

## 样本与计算口径

- 先运行image_id=0作为接线探索，看到结果后按连续ID扩展1/2/3；不是预注册统计实验，不按测试退化程度筛图。每张独立进程，seed20261021，各一次原随机缩放/裁剪/翻转，无手工改GT。
- 使用实际E1权重及原最终层Hungarian匹配；实际前层预测/GT边界并集，而不是GT选区近似。BLL仍weight1/width3，三个核心源码哈希与E1协议一致。
- “原损失”在本报告特指本次同一前向中、含原权重的最终层loss_mask+loss_dice，**不包含分类及辅助层，也不是整个网络总梯度**。
- 比较两个位置：全部最终mask logits，以及共享head.mask_embed[-1].weight。使用autograd.grad，不写入参数.grad，不创建优化器。余弦为负表示该向量整体相反，正值也可以包含局部反向分量。
- 模型状态检查通过并不表示重现了历史训练中的某一步：这是最终权重上的诊断快照，不是36轮过程的梯度记录。

“不足半格”只统计完整有效格，排除图像边缘半格，分母不是所有边缘格或所有图像像素。原损失为采样监督，有些格子原梯度为0；不能把未出现反向的其他格子全解释为同向。

4张图的最终logits整体余弦均为正，说明局部冲突与整体大致同向可以并存。在检查的共享投影参数上2张为负、2张为正，强度依图片变化，不能笼统称“BLL总是太强”。还没有测量整个backbone/decoder或原总损失的梯度。
