# 同格双目标：选择stride4固定子格作为最小修订

2026-11-01。用户要求比较更细网格和每格多个候选，选择最小合理修订。本轮仅本地复用同一批384份增强缓存完成容量比较和设计决策，未连接服务器、未改位置头、未训练。没有扩样、改增强、删GT或调top-K。

## 决策

**选择stride4单位置网格，以stride8隐特征上的四个固定空间子格分数实现。暂不选择stride8无固定空间身份的双槽位。**

目标是解决本计划已证实的标签容量不足，保留“一个候选有一个明确空间位置”的接口。它是原位置头的表示修订，不是新增骨干、MFRM、BLL或已证实的AP改进。

## 相同缓存的实测比较

`scripts/compare-position-grid-capacity.py`读取192图×2次增强，逐图从原GT二值mask计算各网格占据关系，使用最大一对一匹配。三种设置使用相同2350条原小目标增强记录（原面积0<area≤1024、增强后仍保留），同一实例跨增强可重复计数。

|表示|可分配小目标记录|容量不足视图|该反例能否分开|
|---|---:|---:|---|
|旧stride8，一格1位置|2349/2350|1/384|不能|
|stride4，一格1位置|2350/2350|0/384|能，两个不同空间格|
|stride8，一格2槽位|2350/2350|0/384|容量够，但同格两个槽位不自动产生不同坐标|

双槽位匹配实现使用第二槽11次，但匹配目标是最大覆盖，不是最少第二槽；不能据此说有11条必须双槽位。旧规则缺额仍只有1。以上全部是GT辅助容量结果，不是模型候选召回或AP，也不证明3937张图全部增强都不会再碰撞。

失败图2809/XL_344.jpg、seed20263821：

- ID16538（6像素）和ID16539（5像素）在stride8都只有格[14,1]。
- stride4中，两者各自实际占据格[28,2]和[29,2]，最大匹配分别把它们分到[28,2]、[29,2]。
- 对应4像素格覆盖x区间[112,116)、[116,120)，y区间[8,12)；参考中心分别是(114,10)、(118,10)。中心只是query参考坐标，不保证正好落在GT像素内。
- 两目标仍保留原始不同身份及原mask；没有将任何候选移到其GT不占据的格，也没有合并两个标签。

原始证据：`reports/position-grid-comparison-20261101/result.json`，记录384份来源SHA256、逐视图匹配结果、反例分配及脚本SHA256。原预检失败报告保留。

## 两条路线的代价和限制

|方面|更细stride4固定子格（选中）|stride8双槽位（暂缓）|
|---|---|---|
|输出语义|固定左上/右上/左下/右下空间位置|同一粗格中的槽0/槽1|
|仅分数读出参数增量|+387（1通道改4通道）|+129（1通道改2通道）|
|空间参考|由子格坐标直接确定，天然不同|若都用粗格中心，则位置相同；需另明确槽位embedding、固定参考偏置或可学习offset等区分方式|
|身份/监督|沿用GT占据格匹配和原BCE，无额外槽位身份|需明确槽位顺序或置换匹配及未使用槽位监督；不能简单用标注ID大小作为可学习的视觉身份|
|候选分数图规模|原来的4倍|原来的2倍（不含位置/embedding设计）|
|额外学习任务|没有，仍预测位置分数|视设计而定，offset路线还要额外位置监督；embedding路线不一定需要offset损失，但也不保证实例分离|
|尚未证明|粗特征能否预测子格差异、是否过多重复高分|不同槽位能否学到不同实例、是否输出重复|

双槽位并非不能实现，也不一定参数更多；按完整方案，代价取决于槽位区分设计。本次选择stride4的理由是**空间身份明确、保留现有监督与后续位置接口、已覆盖这批目标**，而不是把“更多槽位”判为无效。四个固定子格从表示上也可理解为四个带空间锚定的子槽位；关键区别不是名称，而是每个输出已经有不同且确定的位置。

## 具体最小改法（待实现）

保留C3/C4输入、detach、通道LayerNorm、128通道投影、C4上采样到C3以及stride8的3×3卷积。**仅将最后1×1卷积从128→1改为128→4，再做PixelShuffle(2)**：

```text
原来：stride8隐特征 → 1个分数/格 → stride8位置图
修订：stride8隐特征 → 4个独立分数/格 → 固定空间重排 → stride4位置图
                         左上 右上 左下 右下
```

索引定义：输出`[2*y+dy, 2*x+dx]`取粗格`[y,x]`的通道`2*dy+dx`，dy/dx∈{0,1}。不是先预测一个分数再双线性放大成四份，也不复制四个相同分数。

参数从344577增至344964，新增387。1024×1024输入时位置图从128×128变256×256，单张FP32 logit从0.0625 MiB变0.25 MiB；只是logit张量的理论大小，不是峰值显存或速度测量。昂贵的128通道3×3卷积仍在stride8，不把整个头抬到stride4计算，也不引入R50 C2。末层1×1卷积计算量变4倍，整个模型/整个头不能据此说变4倍。

R50特征没有获得新的原始像素细节；四个输出可以从同一局部特征学习不同子格响应，但是否包含足够细节必须由后续学习验证。此修订消除已知标签容量缺口，不自动消除特征分辨率问题或未来掩码粘连。

## 同步修改边界

下一次实现必须一并改标签/valid mask/选点坐标的stride到4，不能只改logit尺寸。原面积判定、GT身份、占据格最大匹配、分配不足报错、原mask、正负分别平均的BCE全部保留。有效区边缘仍按“格与图相交”保留，完全padding不参与损失或排序。

主K100及20/50/200曲线、无阈值/无距离NMS/无局部峰值抑制不变；主候选数仍100，不变为400。原最终100输出不变。随机对照必须在同一stride4有效网格上采样，step0用新头，不拿旧stride8随机对照直接当新方法的同条件对照。更密的搜索网格会降低随机命中单个指定种子的概率，这是口径变化，必须显式记录，不把它当算法改善。

固定128/64图清单、增强seed、300步/优化器/收益门槛不变。但旧manifest指向旧代码，**不可继续使用旧哈希直接开训**。实现后需生成明确的新表示版本与新代码指纹，保留旧清单及失败记录；验证图片ID/增强seed未变。

近邻验收沿用旧预检已冻结的**46个实例ID对、8张留出原图**，在这些相同GT对上统计两个新种子是否同时入选，不把距离条件直接从stride8≤1格悄悄改成stride4≤1格而缩小问题范围。以两份固定增强为观测，旧规则下属于近邻的具体“图/seed/实例对”观测应从旧分配重建并封存；不同实例对数仍按来源ID去重。新网格近邻集合可另作描述，但不能替换固定主对照集合。

同格双槽位或更细网格都不是无限容量保证。以后若出现两个小目标在stride4也只有同一可用格，继续明确报错，不能因本轮全覆盖就关闭保护。
