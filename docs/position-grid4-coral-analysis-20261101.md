# 珊瑚下降收尾：排序不足与候选集中并存，不能只改前100筛选

2026-11-01。用户授权仅利用已有结果检查珊瑚退化、重复候选和学习/留出差异。本轮本地执行，无服务器连接、无新增前向、无训练；旧300步结果和通过门槛不变。

## 结论

**当前证据不支持把珊瑚下降主要解释为“有好位置，只被第100名门槛截掉”。** 留出组丢失9条记录，其中8条训练后前200格均未接触目标。小鱼重复候选确实严重，但在保存的前200候选范围内，GT辅助去掉明确的小鱼重复位置，只将珊瑚匹配9提高到11，且没有救回那9条原有匹配的丢失记录。

更值得优先检查的是：为什么一些珊瑚位置在学习后排不进高分候选，以及为什么响应集中在少数鱼/珊瑚区域。不能仅凭这些输出证明类别不平衡是唯一原因，不能声称R50没有珊瑚信息，也不能据此自动改损失或再训练。

## 缓存能回答到哪里

实际评价文件只保存K20/50/100/200的有序格编号和统计，**没有完整logit/概率图**。本轮验证top100是top200的前缀，可得前200内确切相对名次；未出现的格只能记为“排名>200/未进入缓存”，不能捏造具体分数或区分“本位置分数下降”与“其他位置分数上升”。

实例对齐键是原图ID、增强seed、annotation_id。保留原类别/原面积，复用同一增强mask，重做与正式评价一致的最大一对一匹配。分析覆盖学习组79条珊瑚记录（51原始实例、19原图、34有效视图）、留出组28条记录（17原始实例、10原图、18有效视图）。同一原始实例在不同增强中可以归属不同转移组，分组distinct GT数不能相加。

## 2. 是100个位置不够，还是位置没有排到前面

留出最终19条未匹配记录中：

- **15条前200格均未触及GT**，其中8条是原先匹配后丢失的。
- **4条首次触及在101–200名**，其中1条是原先匹配后丢失的（图381/GT1372，最终第174名）。
- **0条属于前100已有支持格、却在一对一匹配中被其他实例挤掉。**

同预算K200的珊瑚匹配也从训练前20/28降到训练后13/28；不能靠扩大到200宣称问题解决。GT支持格仍存在、都能分配标签，当前不是之前stride8单槽位容量不足的复发。

## 3. 小鱼重复占位有多严重、能解释多少

在18个含小珊瑚的留出视图的前100候选中，共1800格。step300其中595格只接触一个已标注的原小鱼实例；同一小鱼第一次之后的重复格有562个。图585两次增强中，前100分别94/91格属于这种小鱼区域，存在明显的鱼区域集中。

做了一个**GT辅助、不可部署的受限诊断**：只对“仅接触一个GT、该GT为原小鱼”的格保留每鱼第一个，其他重复格移除；其余格不变，再从原有前200顺序中取最多100格。不删除接触珊瑚的格，不将重叠多实例格武断归给鱼，不从200名以外补候选。此构造不是最优去重上限，也不是新推理规则。

结果：留出珊瑚9→11，只救回图585/seed20261597的GT2288和2296，原始名次183/129。这两条原本就是step0未匹配的，**原先丢失9条没有一条被该受限去重救回**。学习珊瑚40→41，同样未救回其17条丢失记录。

另一些退化视图没有这种小鱼重复占位：图491最终前100有88格不接触任何标注GT；图1881第一seed有87格不接触任何标注GT；图453第二seed主要落在其他GT区域。这进一步说明不能把所有珊瑚下降都归为“鱼挤占”。“其他GT区域”包括大实例，不等于语义背景；本次只定位选点对象，没有识别完整训练因果。

## 4. 不能把宽松覆盖下降解释成完全没学到珊瑚

|指标|学习step0|学习step300|留出step0|留出step300|
|---|---:|---:|---:|---:|
|不同珊瑚匹配数，K100|32/79|40/79|14/28|9/28|
|精确监督种子格命中|0/79|29/79|0/28|4/28|
|触及小珊瑚的候选格数|69|490|29|96|

留出训练前50%是“一个4×4格触及目标就算覆盖”的宽松指标，精确监督点一个都没命中；学习后少数珊瑚的定位变准，但候选在少数目标附近更加集中，独立目标覆盖减少。鱼和珊瑚的集中现象同时存在。因此应描述为**部分珊瑚获得更精准响应，但覆盖更不均衡、留出覆盖退化**，不能概括成所有珊瑚信号都变差。

## 5. 尺寸、增强和学习/留出差异

- 留出丢失9条中8条增强后面积>1024像素，最小一条也有538像素；没有前景消失。它们属于原图面积≤1024的“小目标”，增强后可以变大，不能混用两种面积定义。
- 留出丢失组增强面积中位数9635，救回组3843.5像素；说明退化不集中在增强后最小的几个像素目标。但分组小且非随机，不能推出尺寸越大越容易失败的因果。
- GT3413在图730两次增强中：6480像素时救回、9635像素时丢失；GT1699在图453两次增强中：13832像素时保留、8104像素时丢失。相反方向提示增强敏感性，但不支持单调的“放大/缩小”解释；翻转、裁剪、上下文亦随seed变化。
- 学习组也丢失17条，其中全部落到前200之外；因此这不仅是留出图片陌生的问题。学习组精确种子29/79（36.7%），留出4/28（14.3%），同时存在拟合不均衡和留出差距。
- 学习小目标记录中鱼占1487/1574约94.5%，珊瑚79/1574约5.0%。类别不均衡值得审查，但本轮没有损失/梯度或改变比例的对照，不能把它直接写成已证明原因。

## 当前决策与缺口

不直接添加空间NMS、扩大K或按GT身份去重，也不立即加珊瑚权重训练。**现有证据更优先指向珊瑚位置响应/排序及覆盖集中问题，简单去掉鱼重复候选不足以解释并修复主要退化。**

若下一步继续，最小必要补充是固定这10张留出珊瑚原图的已有增强视图，导出step0/300完整位置分数，并核对前200重现，观察原丢失目标的监督点及占据格分数、全部名次和竞争对象。只做已有权重前向，不训练；本轮未执行该补充。没有完整分数之前，对“绝对分数压低”与“其他位置分数抬高”的区分保持未决。仍不进入完整mask分支。

脚本`scripts/analyze-grid4-coral-regression.py`；证据`reports/position-grid4-coral-analysis-20261101/result.json`保存逐实例、逐视图、来源哈希及受限oracle。所有step0/100/300的学习/留出珊瑚计数与正式结果一致。README、AGENTS、实验计划更新，本地提交，推送由用户负责。
