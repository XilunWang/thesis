# 有效区域匹配开关接入验收结果（2026-10-31）

接入验收通过。新增默认关闭的独立head选项，只控制匹配点采样区域；没有启动训练，没有参数更新，没有新增网络参数。此次结论是工程可用性，不是AP改善。

## 实际改动

新增scripts/valid_region_head.py中的ValidRegionMask2FormerHead，继承原Mask2FormerHead；match_valid_region默认False，配置类型要求布尔值。

- 关闭：_get_targets_single直接调用原父类路径。
- 开启且有padding、有GT：原12544个均匀随机坐标乘有效宽高/GT画布宽高，只改变匹配的采样位置。点数、RNG消耗、分类/BCE/Dice权重、原assigner/sampler及标签生成规则保持原逻辑。
- 无padding或空GT：回到父类路径；空GT无正样本匹配需求，不额外改其处理。
- 有效尺寸超出GT画布或非正数时报错，不静默截断。

forward、predict、loss_by_feat、_loss_by_feat_single均继承原函数，验收脚本检查方法身份相同。原mask loss的采样和公式没有修改；开启后分配的正样本可能变化，因此实际loss数值可以变化，不能称所有loss值保持不变。

configs/valid-region-head-probe.py是默认关闭的head覆盖片段，仅供显式合并配置，没有Runner或训练命令。没有修改E0/E1/E1-P正式入口，也没有接入BLL、MFRM或DSGAT。

## 已做到与未做到

现在可以显式选择这个独立head并开启匹配区域选项，正常计算原损失和反传；默认仍关闭，正式模型配置不变。它改变训练分工，而不是推理阶段的掩码或分数修补。

上一轮固定前向下的匹配几何改善，不能当本轮模型训练收益。还没有执行任何optimizer.step，没有完成优化器保存恢复、连续训练等价、短试跑或正式AP评估，也未全面检验所有数据/硬件/分布式模式。

下一建议先检查模型、优化器及开关配置的保存恢复，并冻结固定少量真实图片的短试跑协议；之后获得参数更新授权再执行短试跑，不自动开始36轮。仍保持只改匹配采样这一因素，不顺带修改原mask loss采样或匹配权重。
