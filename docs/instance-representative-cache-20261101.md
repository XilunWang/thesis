# 实例内部代表点与重复约束：缓存可行性验收（2026-11-01）

## 结论

在本次已有缓存范围内，能同时定义“每个目标内部一个独立代表点”和“压低其余重复候选”，且不把相邻小目标代表点误当负样本。通过的是GT辅助的监督定义、匹配容量和对位置logit的导数方向验收，不是训练效果或推理召回验收。

只进行本地CPU缓存运算，无服务器、模型前向、参数反传、优化器更新或新训练。原训练脚本、位置头、权重和前100推理选点均未修改；原300步试验的珊瑚门槛仍未通过。

## 本次具体方案

1. **目标内部选点。** 原始面积0<area<=1024的每个实例保留自己的GT编号和全部stride4占据格，候选只能来自其自身支持区域。按当前缓存分数偏好排序，实施最大基数的一对一匹配；共享格不能分给两个目标。先处理支持格少的实例，再按ID排序，可沿增广路重新分配，不能直接各取最大值后丢掉冲突目标。该算法偏好高分，但不承诺总分最优。
2. **保护全部代表点。** 先汇总所有目标的代表格，全部标为正。某个代表格即使也落在邻居的支持区域，仍不能成为任何实例的重复负样本。
3. **重复格只计一次。** 在小目标支持区域并集中，除去全部代表格；剩余格仅分配给实际支持它的一个实例，按到代表格的网格距离及GT编号确定归属。不给同一格叠加相互矛盾的目标。
4. **约束三部分。** 代表点正BCE；每实例内重复格相对代表点的排序损失；小目标支持并集之外保留负BCE。这里只分别检查各项，不选择正式训练权重。支持并集之外可能有大目标，不等于语义背景，沿用当前小目标位置任务的范围。
5. **容量不足明确失败。** 如果两个实例只有同一个可用格，返回不可行，绝不静默删目标或合并ID。没有空间距离NMS，也不因为两个代表点相邻而删掉其中之一。

重复项的具体审查式：对有重复格的实例，先对其重复格平均`softplus(z_duplicate - z_representative)`，再对实例平均。选择与归属在本次导数检查中固定，不对离散匹配求导。该项会提高代表点并压低重复格；它不要求把整个实例区域都变成正样本，也不直接惩罚邻居的代表点。

三项单位权重求和仅用于核验符号，**不是确定正式损失配比**。正样本BCE负责让代表点本身有正响应，重复排序项只管同实例内高低，区域外负项继续约束非候选区域。

## 为什么必须全局保护代表点

邻近压力检查中，简单地“每个目标自己选最高格”会出现2次格子冲突。一对一匹配完成重新分配后没有丢失目标。

如果重复负样本仅排除本实例代表点，邻居代表点仍可能落在自己的支持格中。这批两种压力排序累计产生30处潜在跨实例正负冲突；先排除**全部**代表格后为0。30处是按实例/格及排序计数，并非30个不同真实失败目标。

历史微小目标16538/16539在4×4网格上选择索引540/541（x=28/29，y=2），两种排序时归属可交换，但各实例都有自己支持范围内的独立格。两格相邻，重复约束对两者的logit导数都指向提高分数，没有把任一方压低。全部98次目标对压力检查中，19次代表点只隔一个细格，也都保留。

这保证的是缓存上的独立监督位置，不是后续mask身份或分割输出必然分离。共享支持格或一格同时触及两个GT时，分配独立位置不等于视觉可辨性已解决。

## 与之前单点监督有什么不同

以前：几何规则固定指定一个点，目标内部其他位置都是负样本。

现在审查的候选：仍然每目标只选一个正代表，但允许在目标自身支持范围内按当前响应选择；其余格作为重复竞争者进行约束，并保护邻居代表点。不是整片前景全正，也不是按距离删峰。

step300的28条珊瑚都能用自身区域最高格作独立代表，均不同于原几何种子。原种子会进入重复集合。step0有27/28发生同样变化。这说明当前标签确实可以从“固定几何点”改为“实例内代表点”；**并不说明这样选出的点一定更适合分割。** 本批74个小目标两阶段都没有自身最高格的共享冲突，邻近冲突主要由额外固定几何压力案例检验。

GT辅助匹配能让74/74有代表，是使用真实标注和完整支持集的结果，不能报告为模型召回100%。原来的预测、top100排序和珊瑚14→9覆盖结果完全不变。本次也没有把31,145个重复格从预测中删掉；仅验证它们有明确、无冲突的压低目标。

## 尚不能证明什么，以及下一步

- 对logit的导数方向通过，不代表共享网络参数更新后各目标分数都会按相同方向改变，更不代表AP改善。
- 动态代表点可能强化已有错误偏好，尤其初始随机位置响应；本轮没有检验选点随训练变化的稳定性。
- 一对一分配避免共享格合并；若新样本出现不足的支持容量仍会失败。这里不是3937张全量验收。
- 尚未确定三项损失的正式比例、实际训练实现及恢复协议，不具备开训结论。

建议只把这一规则作为可进入后续无更新接入审查的候选：先固定目标定义及训练起点，再检查实际实现是否遵守全局正点保护，以及原模型冻结/梯度隔离是否保持。不要直接增加训练步数、在这批缓存上反复调阈值，或用GT辅助结果宣称收益。
