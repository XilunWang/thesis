# 原训练增强可见性审计结果（2026-10-31）

本次没有找到支持立即修改增强并重训的明确问题。抽查中非空标注没有因缩放而消失；裁剪会移除目标，但每个原始小目标都至少在三次增强之一保留。不能把正常随机裁剪直接认定为漏检根因，也不能据此排除其他图片或随机种子的缩放风险。

## 范围和核验

按[冻结协议](baseline-augmentation-protocol-20261031.md)，复用全3937张训练图既有固定增强记录，另选47张真实训练图，每图3个固定种子，运行141次原E0数据处理。只使用CPU数据pipeline，没有创建模型或优化器，没有训练、推理或修改权重。官方划分及重复图不变。

逐阶段追踪临时用实例索引携带对应关系，打包前恢复类别；141次均与未插桩原pipeline的图像、掩码、类别精确一致。原标注哈希未变，服务器下载文件哈希核验通过。此次脚本检查成功，不等于模型效果验收。

## 逐实例结果

47图包含244个非空普通实例，每个重复3次，共732个实例增强记录。以下尺寸按增强前栅格掩码像素面积分组；选图时用COCO标注面积，二者不混称。记录数不是独立目标数，也不是实际36轮曝光统计。

| 原始尺寸 | 独立实例 | 增强记录 | 保留 | 缩放归零 | 裁剪移除 | 非空裁剪后被过滤 |
|---|---:|---:|---:|---:|---:|---:|
| 极小，面积<256 | 38 | 114 | 88 | 0 | 26 | 0 |
| 其他小目标，256≤面积<1024 | 62 | 186 | 159 | 0 | 27 | 0 |
| 中目标，1024≤面积<9216 | 91 | 273 | 223 | 0 | 50 | 0 |
| 大目标，面积≥9216 | 53 | 159 | 158 | 0 | 1 | 0 |
| 合计 | 244 | 732 | 628 | 0 | 104 | 0 |

100个原始小目标的300次记录中，53次被裁掉（17.67%）；但这100个目标均至少在一次增强中保留。只有2个中目标三次均未保留。原始极小目标仅1次最终剩1–15像素，不支持在本样本中“缩放频繁把小目标弄没”的猜测。

裁剪也可能截断保留目标：极小/其他小/中/大分别7/20/39/12次保留面积不足缩放后的一半。这是可见性变化记录，不能直接等同训练缺陷或漏检原因。47图按类别与尺寸取前几个ID，是便利样本，不能将上述比例外推全训练集。

## 既有全量记录告诉了什么

全3937图每图一次固定增强，3936图保留、ID976被原pipeline过滤；共22033个普通实例。增强后面积<256有3012个，256–1024有3379个，中目标6570个，大目标9072个；其中240个面积只有1–15像素。极小实例确实存在，但旧记录没有逐原始实例对应，不能据它定位是原来就小、缩放变小还是裁剪截断。

保留实例按类别为鱼12956、珊瑚6649、水草928、沉船200、潜水员465、机器人70、海底765。类别数量仍不均衡，但既有原始数量本来就不均衡，不能认定数据处理额外压制稀有类，更不能把一次增强数量当真实训练曝光次数。

## 决策和下一项

不直接删除裁剪、提高缩放下限、增加类别权重或启动新训练；本轮证据不足以支持这些改动。BLL路线保持结束，MFRM设计保持暂停。

下一建议：固定E0和原输入尺度，针对预先固定的小目标漏检及对照图片，查看进入最终类别top-k选择前的全部query掩码。已有保存结果是query×类别候选筛选后的top100，并不保证包含100个不同query。需要区分：①原始query也没有合格掩码；②已有合格掩码，但类别判断/背景概率或候选筛选使其没有进入最终结果。前者才继续查空间特征与掩码形成，后者优先查类别学习和候选选择。不调阈值、不替换正式预测，不将GT辅助诊断当作可实现AP。这项检查尚未执行。
