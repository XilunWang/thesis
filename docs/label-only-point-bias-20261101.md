# 位置监督选点偏向检查（2026-11-01）

本轮本地缓存与源码检查完成，无服务器连接、模型前向、反传或参数更新。发现新选点规则更偏向边界附近，具备提出一项保守修订的依据；尚未建立它导致背景高分的训练因果，不授权训练。

## 先纠正证据范围

`run-label-only-pilot.py`每步日志只有step、loss、gradient_norm、elapsed_seconds。标签由每次前向的当前分数动态生成，但没有保存600个训练视图访问时的实际代表点。不能从最终权重恢复历史选点。

本次固定12图属于位置头holdout，未参加该位置头训练。重放其58个已标注小目标在现存四组logits下的标签规则，只能说明该规则在这些图上会怎么选，不能声称已经查到训练当时教了哪些纹理。它们仍来自官方UIIS训练划分，holdout是位置头内部划分。

## 源码事实

- 旧规则：靠近本实例前景质心的格优先，再通过一对一匹配避免相邻目标共享格子。
- 新规则：在本实例的支持格内按当前分数优先，一对一匹配；分数detach不反传穿过选点过程。
- “支持格”定义是4×4内任意一个标注像素，而非中心必须在实例内，也非16像素全前景。因此“目标内部代表点”的表述需要收紧为“与目标相交的格”。这是原几何口径，不是本轮发现越界代码错误。
- 新旧均是每图正负样本分别求平均再等权BCE，不新增纹理识别约束。目标内部未被选为代表的格也属于位置负标签，不是语义背景。

## 背景是否被错误直接当成正样本

此前12个标注外高分格，在全部四组分数下重放规则均不是正样本（48项）。按当前BCE，其直接logit监督方向是压低，不是抬高。它们在holdout上没有实际参与此次损失，不能把这个符号当训练时施加的梯度。

因此不支持“代码把这些纯背景格直接标成目标”的解释。更合理但仍待证的机制是：动态选点容许边缘混合格；当前偏好被选为正监督后可能自我强化；共享特征在未训练图的相似局部结构上出现高分。当前检查没有训练代表点历史、特征相似性或受控干预证据，不能把这个机制写成已证实根因。

## 决策

有一个具体、有限的修订候选：保留每实例独立代表、原损失与预算，选点优先考虑本实例覆盖更充分的格子，再使用分数排序；不能简单删除所有边缘格，因为真正极小/细长目标可能只有部分支持格，相邻实例还可能争同一格。

若继续，先用已有增强GT做一次无模型几何可行性检查：内部优先能否减少中心落外，同时维持全部原有实例的一对一可分配性；不足时保留原支持作为回退。没有完成该检查前，不实现正式训练规则、不启动300步或长训。即使几何通过，也只说明没有丢目标，不保证AP或背景响应改善。

如果不能形成保持实例数量的明确规则，或后续受控对照不改善，则停止这一选点方向；不再泛泛检查纹理或通过放宽评价标准过关。本轮不改既有失败判定。
