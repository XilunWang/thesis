# 位置头与原版漏检缓存对应核查（2026-11-01）

本轮只读取已有本地缓存，无服务器、无模型前向、无训练。完成身份/数据划分/增强/目标映射审计；结论是**现有缓存不足以衡量位置头对原版漏检的互补性**，不能报“救回0个”，也不能拿530个覆盖目标当原版漏检补救。

## 核查对象与对应要求

对应至少需要同一官方split、同一原图、同一变换后GT及目标身份；严格输入对照还需要相同输入张量、模型权重/模式和可明确解释的预测后处理。图像ID、GT ID在不同split中可能重复，不允许跨split按整数直接连接。

位置头三组结果都基于官方train的192图、384个固定增强视图，其中learn128图/256视图，head-holdout64图/128视图。原E0此前训练过官方train，head-holdout仅指位置头未学习过。

原版69个小目标漏检来自官方val24图的固定score≥0.5、同类mask IoU≥0.5诊断，不等同AP遗漏。原版691图完整预测同样属于val；逐解码阶段、形状和3图特征探针沿用val样本，不能因都叫E0而与train增强结果直接配对。

## 唯一可对齐的train预测案例

图片317=`L_333.jpg`，seed20261329，属于位置头learn而不是holdout。

原版匹配诊断缓存和位置头缓存的四个GT mask逐像素完全一致、类别一致；据位置头保留身份，可将其中一个原面积≤1024的小实例对应到GT1079（潜水员，原标注面积322.87，增强后423像素）。

原版缓存query69：mask IoU0.69264，正确类别概率0.99374，mask质量0.97676，乘积约0.97064。旧几何、自适应、覆盖优先三个位置头均命中该GT支持区域。

这说明唯一有用的重合案例原版已经存在几何和类别均较好的候选，不能提供“位置头补救原版漏检”的证据。不能从一个例子外推它只会找容易目标。

该原版缓存为model.train、冻结BN的训练匹配诊断，mask被上采样到padding后的增强尺寸；位置头为E0 eval特征。旧缓存没有保存输入张量hash，因此即使seed与GT完全一致，也不宣称输入逐位一致或它等价于正式val检测结果。上述分数仅为缓存候选诊断，不重新命名为正式TP。

图片317的另一增强seed21261329没有对应原版预测，不能用第一次增强的预测替代。

## 路线判断

- 目前没有证据证明位置头已经补到原版漏检的小目标；也没有证据证明补救数为零。
- 既有300步结果自身未通过目标外候选门槛，且还缺少与原版失败目标的关联，不支持继续调参训练、全量训练或直接接入query。
- 在路线设计上，之前验证位置覆盖时没有同时缓存相同输入下的原版实例输出，导致现在无法闭合“位置覆盖→原版缺陷”的证据链。该缺口应如实记录，而不是用不同split或不同增强拼出结论。

如果用户仍愿意给这条路线一次最后的低成本确认，最小缺口是：**在已有位置头holdout输入上，补原版E0完整实例输出**。例如沿用已有12图固定增强，输入/GT哈希必须精确一致；用相同坐标下预先固定的一对一类别/IoU/分数规则区分原版已检出和漏检，再与三版已有位置候选逐GT连接。只需原版前向，不训练、不重跑位置头；若该批漏检很少则明确样本不足，不自动挑图扩样。

这是下一项可选协议方向，不是本轮执行授权，也没有保证能提高AP。即使发现位置头覆盖了漏检实例，也只能证明位置提示有互补，不能证明query接入一定能画出更好掩码。
