# 原版逐解码阶段候选诊断（2026-10-31）

结论：小目标问题同时包括“各阶段均未形成合格独立掩码”“早期候选后来退化”“有形状但类别置信低”。确有后续扩大、合并或移走的例子，但不支持简单去掉最后一层、保留早期掩码或直接添加MFRM。

## 范围与验证

按[冻结协议](baseline-decoder-audit-protocol-20261031.md)，沿用上轮全部45个几何失败和22个低分对照，合计67个GT、15张图；没有按本轮结果重新选样。E0 epoch36、原尺度(1333,800)、FP32、batch1，单次原head.forward提取S0至S9：S0是初始query预测，S1–S9是9层Transformer解码更新后的预测。S0不应称第一层decoder。

每阶段检查全部100 query。双线性上采样、去padding、还原原图、logit>0及最终top-k与原实现一致。S9输出1500条预测与原保存结果分数误差0、掩码变化0；模型状态、权重、标注、原预测不变，无梯度、优化器或参数更新。

服务器文件已下载并核对哈希，本地从每阶段原图RLE重算全部query与67个GT的IoU，与服务器逐条一致；S9最佳IoU与上一报告逐条一致。脚本、选择清单与本地现有输入哈希也核对通过。运行结束GPU占用0 MiB，没有关机。

## 45个最终失败目标，之前有没有好候选

- 32个：S0–S9始终没有任何query达到IoU≥0.5。
- 13个：S0–S8曾有IoU≥0.5候选，S9没有。若排除初始S0，只看更新后的S1–S8，曾有者为12个。
- 这13个里，早期曾达到IoU≥0.75的只有3个，不能把所有过0.5的候选称为边界精细。
- 45个中仅1个曾同时满足同类top100入选、最终分数≥0.5和IoU≥0.5：GT362的S8；其最佳IoU从约0.508降至S9约0.493，是接近门槛的波动。

13例是跨层跨query用GT找出来的候选可用性，不是可部署检出增益；没有把这些候选替换正式输出。

## 固定同一query追踪，发生了什么

对上述13例固定各自早期IoU最高候选的query索引，追踪到S9：

- 10例仍覆盖原目标，但预测面积扩大；其中4例新增覆盖了其他标注实例至少50%，有更直接的实例混合线索。
- 3例最终与目标交集为0：GT280的该query最终掩码为空；GT463和GT1437的该query转移到其他位置。固定query索引是计算槽位，不保证语义身份始终一致。

具体案例：GT124的query77从S6 IoU0.612降至S9 0.401，面积557→1913；GT126的query49从S1 0.762降至S9 0.249，面积237→805，都从较独立的区域扩大到邻近标注。它们早期正确类别概率仅约0.010/0.023，说明只保留形状仍不足以作为可靠预测。

GT125/127则所有阶段均未达到0.5；不能用GT124/126的退化机制解释同图全部漏检。GT1437先前已有标注范围疑点，其变化应单列，不能直接当结构改进的强证据。

## 下一步判断

目前有证据的研究问题是“独立实例形成/保持与正确类别确认”，不是单纯最后一层边界不锐利。暂不新增BLL、MFRM或提前退出/层融合，不启动训练。32例各层均无合格候选不能说明骨干完全没有特征；13例早期退化也不能证明某个注意力算子有错；还没有闭合训练原因。

建议下一项转到固定少量真实训练图，核对原训练的一对一匹配：哪个query被指定学习哪个GT，几何较好的低分query是否被当无目标、真正分配给该GT的正样本是否形状较差。匹配、分类和掩码代价需来自同一前向/固定采样点，不改变匹配或更新参数。这能检验训练分工与输出表现是否有关，而不是继续对测试案例试模块。应先冻结训练图与判据，匹配正常或无明确关联时停止扩展这条机制猜测。该检查尚未执行，没有新训练授权。
