## 尚未通过的关键条件

“同种子”不保证相同随机轨迹：DirectQueryFeatureHead额外构建两次Conv2d，默认随机初始化之后才清零，可能消耗CPU RNG；数据加载器worker启动及损失点采样也有随机状态。最终权重为零不代表这些随机状态没变化。因此旧A协议资料可用，但严格配对复用尚未批准。

后续无更新入口检查应重建封存A启动流程和候选启动流程，固定加载顺序，比较采样器/worker种子、首批图ID、增强后输入/GT指纹，以及进入loss采样前CPU/CUDA RNG。若候选需补偿随机数消耗，应基于实际启动调用次序记录并回归，而不是只给候选重新seed。重放启动流程不能冒充已有历史逐步数据轨迹；旧A未保存每步增强指纹，因此即便启动检查一致也要明确复用的证据范围。

另外检查实际新增参数学习率与衰减、初始优化器空状态、保存后重新加载；用标为diagnostic_only的非空状态夹具做无step恢复检查，只证明序列化路径，不声称真实更新后的中断恢复已验。训练时有限loss/梯度检查、预算停止、目录拒绝覆盖与仅末轮评价仍需新的独立运行契约。
